# 专题任务交接

所有任务先读 AGENTS.md。初始任务仅交付设计与技术验证材料；软件实现以被接受的 ADR 和接口为前提。以下路径为提案文档所有权，其他目录暂不分配实现权。

## 程序：docs/proposals/desktop-runtime.md

检查本机可用工具链，对比最多两种适合 Windows 透明桌宠的技术方案。提出窗口、动画播放器、拖动、缩放、退出、位置保存、多显示器和 DPI 的验证方式。说明动画与业务事件如何分离。不得自行读取聊天数据库或修改 Codex。交付可核验的选择理由和最小实现边界，不先搭一个与其他任务接口冲突的大项目。

## 动画：docs/proposals/animation-spec.md

从 docs/aemeath-reference-notes.md 获取视频和用户选择。区分实际看到的动作、需要进一步查看的片段、为桌宠原创的拖动姿态。提出像素网格、透明背景、基线、每帧尺寸、时长、循环/单次动作和命名约定。不要把生成概念图直接当成已对齐的图集；不要下载或提交整个第三方视频。未经用户重新选择，不采用第一版长发 Q 版造型。

## 联动：docs/proposals/codex-integration.md

核查真实可访问的本地或官方事件接口。提出与桌宠程序无关的状态协议，覆盖 idle、working、waiting、completed、failed、unknown，包含事件时间和任务标识。说明同一事件重复、乱序、断连、状态过期、多任务并行的策略。只读调查；不上传会话、不抄取令牌、不把工具对当前对话可用等同于外部程序能调用。找不到正式接口也算有效调查结论。

## 测试：docs/proposals/acceptance-matrix.md

独立列出正常/异常场景：鼠标拖动中任务完成、松手恢复、显示器拔除、DPI 改变、程序重启、损坏素材、事件乱序与重复、连接断开、无障碍退出入口。将自动化测试与需要真实 Windows 桌面的手工验证分开，不宣称尚不存在的测试已通过。首次只编写验收矩阵，待实现 PR 出现后评审真实变更。

## 提交与回报

各任务在自己的 codex/ 分支提交分配文档。远程已可用时创建 Draft PR；无 CLI 身份时交付本地提交哈希并报告阻塞。不要自行合并。回报必须包含产物路径、实际验证和待统筹决定的问题。
