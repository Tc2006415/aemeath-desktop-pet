## 执行约定与待接受策略

每次执行记录：用例 ID、提交/包版本、运行方式、Windows 版本、显示器布局/分辨率/DPI、素材版本、事件来源（模拟或真实）、前置条件、实际步骤、预期与实际、证据位置、结论和缺陷链接。证据只保留合成任务标识、状态和必要时间，不附完整对话、凭据或私人桌面内容。

结果使用「未执行／阻塞／通过／失败／经统筹批准不适用」。依赖未定为阻塞，不计通过；没有记录为未执行。每个矩阵行默认未执行。A 为未来可自动化测试，W 为必须在真实 Windows 应用执行的手工检查，R 为真实来源联动检查；A 通过不能替代 W 或 R。

下表是需要统筹与所有权任务接受的测试判据，不是现行接口。符号只用于描述测试，不要求实现采用同名字段。

| 决策 | 建议验收方向 | 接受前的影响 |
| --- | --- | --- |
| D1 拖动与业务状态 | 拖动反馈临时覆盖表现，任务状态继续更新；松手依据最新有效状态恢复，不恢复按下时的旧状态 | A02–A04、W03 的具体表现阻塞 |
| D2 完成/失败呈现与恢复 | 明确单次动作是否排队、显示时长、拖动中完成是否在松手后补播，以及终态何时返回 idle；安全底线是不得丢失最新有效结果或无限卡住 | 终态时长与恢复断言阻塞 |
| D3 事件可信度 | 明确同任务的身份、顺序、重复判定、重启后的新任务周期及未来时间偏差处理；旧事件不能把新状态覆盖 | A05–A08、R03 的精确输入阻塞 |
| D4 断连与过期 | 明确过期阈值 T、断连检测时限 C、边界是否包含等号、重连如何取得可信新状态；失去可信状态显示 unknown/离线，不推测 completed | A09–A11、R02–R03 的时间断言阻塞 |
| D5 多任务 | 明确多任务显示选择、聚合或切换方式；一个任务完成不能让仍工作的其他任务被误报为全部完成 | A12、R04 的展示断言阻塞 |
| D6 窗口与素材 | 接受 DPI/坐标规则、缩放范围、离屏恢复区域、素材格式/帧时长/基线和损坏素材降级方式 | A13–A16、W04–W09、V02 的数值断言阻塞 |
| D7 支持与交付 | 确定 Windows 支持版本、测试设备组合、可访问的退出路径和性能预算；运行方式由 ADR 确定 | 发布环境覆盖和性能门槛不能宣称已满足 |

T、C 和播放时长由被接受的规格提供，不在此编造秒数。边界测试取阈值之前、恰好阈值、之后；采用可控时间避免靠长时间等待。未接受决策时仍可检查崩溃、虚报成功、不可退出等底线，但不能给依赖策略的整行判通过。
