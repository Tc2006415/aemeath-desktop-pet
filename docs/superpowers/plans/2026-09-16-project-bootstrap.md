# 仓库与协作启动工作计划

**Goal:** 建立可追踪、可评审、职责清楚的 GitHub 与 Codex 多任务开发流程。

**Architecture:** 当前任务统筹，四个专题任务各用独立 worktree，通过文档提案和 PR 协作。实现前由统筹统一平台与接口。

**Tech Stack:** Git、GitHub、Codex 任务；桌面实现技术栈由 ADR 0001 决定。

**Spec:** ../../development-workflow.md

## 约束

- 仓库默认为私有，名称 aemeath-desktop-pet，可按用户指定调整。
- 远程仓库创建并推送初始提交后，才建立专题任务。
- 不修改 Codex 安装包，不上传会话和账号信息。
- 此计划仅启动协作流程，不代表桌宠功能已经实现。

## 启动清单

- [x] 收集现有需求与只读技术调查。
- [x] 编写 README、AGENTS、开发流程、ADR 提案、任务简报和 GitHub 模板。
- [ ] 验证文档路径、Git 差异与初始提交。
- [ ] 用户在浏览器完成 GitHub 登录；确认目标账号可创建仓库。
- [ ] 创建私有 aemeath-desktop-pet 仓库，绑定 origin 并推送初始提交；若 Git 认证不可用，报告并完成官方认证方式。
- [ ] 在 GitHub 建立程序、动画、联动、测试四个首阶段 Issue，写入目标、依赖和验收。
- [ ] 基于已有项目创建四个独立 worktree 任务，传入对应简报、仓库地址和 Issue。
- [ ] 检查新任务实际启动状态，向用户交付仓库链接和任务入口。
- [ ] 汇总四份提案，接受运行方式 ADR，制定各模块实现计划。
