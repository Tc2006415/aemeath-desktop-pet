# 爱弥斯像素桌宠动画规格提案

状态：供统筹审阅，未接受；2026-09-16。关联 [Issue #2](https://github.com/Tc2006415/aemeath-desktop-pet/issues/2)。

本次仅交付规格和参考证据整理，不含动画成品、播放器实现或共享接口变更。以下尺寸、帧数、时长、优先级均为制作建议，不是游戏实测值，也不是已确定的运行时协议。实施以统筹接受 ADR 和素材接口为前提。

## 1. 依据与证据边界

已阅读 README、AGENTS、开发流程、任务简报、[ADR 0001](../adr/0001-runtime-selection.md) 和 [参考笔记](../aemeath-reference-notes.md)。2026-09-16 通过已登录浏览器读取 Issue #2，其验收覆盖参考可信度、像素规格、待机/拖动/状态动画和 Draft PR。

本任务实际视觉检查了 [第二版概念图](../../assets/concepts/aemeath-game-style-v2.png)：三幅并列角色分别表现睁眼、闭眼笑和倾头眨眼；可见粉色头发、蓝色尖顶头饰、紧凑身体和低位羽状装饰。画面带灰色背景，人物位置和姿态有差异。它提供造型方向，不能证明透明通道、统一像素网格、帧间对齐或动作连续性合格。未把第一版长发 Q 版作为依据。

## 2. 方案选择

| 方案 | 优点 | 成本与边界 |
| --- | --- | --- |
| 推荐：独立桌宠逻辑像素素材，逐动作导出 | 帧数和时长可独立调节；方便多待机、拎起/悬停/落下组合 | 依赖 ADR 接受及程序任务确认加载格式；当前不能宣称可运行 |
| 备选：Codex 内置兼容皮肤 | 可围绕已有皮肤槽制作精简版本 | 参考笔记记录第二版图集 1536×2288、8×11 格、单格 192×208、idle 固定 6 帧；这些是既有只读调查结论，本任务未复核，也不等于公开受支持的接口 |

推荐保留独立的动作源帧，再按被接受的运行方式导出。即使采用内置皮肤，也不能把本提案动作名直接映射为其状态名；多待机和专用拖动入口尚未确认，不承诺放入图集即可实现。不得修改 Codex 安装包。最终运行方式由统筹决定。

## 3. 建议的像素与素材规格

以下先用于制作一组待机试样，视觉验收通过后才冻结尺寸；如羽饰或拖动姿态放不下，统一调整画布，不对单个动作临时放大或裁切。

| 项目 | 建议值与含义 |
| --- | --- |
| 逻辑画布 | 每帧 96×104 px；所有动作相同画布。坐标原点左上，x 向右、y 向下 |
| 像素网格 | 最小绘制单位 1 逻辑像素；不旋转或缩放已完成的帧来冒充新姿态；避免插值产生杂色 |
| 固定锚点 | 画布坐标 (48, 94)，位于下方中央；所有帧保持此锚点，不按非透明包围盒自动居中 |
| 落地基线 | y=94 的水平边界，站立/坐姿的最低接触像素通常在 y=93；羽饰允许伸向两侧但不随表情产生整体漂移 |
| 安全区域 | 建议所有可见像素位于 x=4…91、y=4…99；超出即重新评估构图。画布边缘至少保留 4 px 透明留白 |
| 透明背景 | PNG RGBA，初版角色像素 alpha 只用 0 或 255；无灰底、棋盘格底或烘焙阴影。少量光点也用离散实色像素 |
| 色彩 | 以概念图和后续游戏核查建立共享色板，建议先控制在 24–32 个可见颜色；粉发、蓝饰、深浅服饰分组。此色数为制作预算，未从概念图测得 |
| 输出倍率 | 推荐源帧 1×，显示采用最近邻整数倍率。若导出 2×，每格为 192×208，锚点相应为 (96, 188)，不把两套倍率混入同一包 |
| DPI | 逻辑网格与窗口坐标换算由程序负责。非整数系统 DPI 下的最终清晰度须在真实窗口检查；本提案不保证仅靠最近邻就消除全部缩放问题 |
| 时间单位 | 正整数毫秒，按每帧时长播放；禁止用显示器刷新次数定义动画速度 |
| 帧率与停留 | 主动作建议每帧 100–150 ms，关键表情允许长停留；避免复制大量相同帧仅为延长时间 |

初版以粉发轮廓、尖顶蓝饰、闭眼笑及低位羽状装饰建立识别度。保持紧凑头身比，不向第一版长发造型回退。左右细节可能不对称，默认不自动镜像；若需朝向变化，另行检查头饰和羽饰。工作/等待/失败除颜色外还要有不同姿态，防止只靠色差辨识。

## 4. 动作容量与节奏草案

以下均未制作。编号仅是提案内的素材标识，不能作为外部状态协议。总时长是逐帧时长之和，循环动作指一周期；时长列表顺序对应 000、001……帧。所有原创姿态都必须经过造型检查，不能声称来自视频。

| 素材标识 | 来源与拟定表现 | 帧数与逐帧时长（ms） | 播放与结束 |
| --- | --- | --- | --- |
| idle-soft | 桌宠原创：轻微呼吸、头发/羽饰 1 px 起伏；造型参照像素小爱 | 6；[400,150,150,400,150,150]，1400 | 循环；首尾构图一致 |
| idle-smile | 原创表情连接；闭眼笑参考已记录造型，连接过程未经视频验证 | 6；[120,120,500,120,120,220]，1200 | 单次，回 idle-soft 中性姿态 |
| idle-perform | 后续可选：将人形表演转译成像素小幅摆手和光点；非实机复刻 | 8；[150,150,200,200,200,200,150,150]，1400 | 单次，回中性；完整视频核查后才排产 |
| drag-pickup | 原创：抬头、身体收紧、脚部离开基线；头饰不是被拉扯变形的把手 | 4；[80,80,100,100]，360 | 单次，接 drag-hold；可提前松手 |
| drag-hold | 原创：悬停、小幅摆腿/羽饰；不根据鼠标速度倾斜整张图 | 4；[180,180,180,180]，720 | 拖动期间循环 |
| drag-release | 原创：落稳、轻微下沉、回中性；位移在帧内，窗口位置由程序管理 | 4；[80,100,120,160]，460 | 单次，恢复最新有效业务表现 |
| task-working | 原创：专注、节律性小手势；没有真实任务时只允许标注 mock 的预览触发 | 6；[160,160,160,160,160,160]，960 | 有效 working 期间循环 |
| task-waiting | 原创：抬眼/举手后安静停留，区别于工作动作 | 4；[200,200,800,200]，1400 | 有效 waiting 期间循环，不频繁闪动 |
| task-completed | 原创：闭眼笑、抬手、少量光点，回中性 | 6；[100,120,180,400,120,180]，1100 | 有效完成提示触发一次；动画结束不改写业务状态 |
| task-failed | 原创：低头/垂手、收起光点、恢复平静 | 6；[120,120,250,400,150,160]，1200 | 有效失败提示触发一次；失败事实另由状态呈现保留 |
| status-unknown | 原创中性静态姿态，不庆祝、不假装工作或失败 | 1；[1000]，1000 | 循环等同静态；程序显示未知/离线标识 |

基础包不含 idle-perform 时共 47 帧、10 条动作；加入该可选动作后 55 帧、11 条。这里的“帧”是导出帧数预算，不保证每帧都需独立绘制。机甲互动、持武器、走路和形态转换均不在首批范围。

可选随机待机建议只在有效 idle 且未拖动时安排 idle-smile，每次间隔 8–16 秒，返回 idle-soft 后重新计时；idle-perform 只有核查及验收通过后才加入。此调度建议不改变事件语义，程序也可先只播放 idle-soft。

## 5. 动画播放与任务状态的边界

提出两个独立维度供统筹评审：业务状态由联动层确认，鼠标交互表现由程序层确认。动画素材只负责视觉表达，不读聊天记录、不推断任务是否完成，也不决定多任务聚合、去重或过期阈值。

建议交互表现顺序为 drag-pickup → drag-hold → drag-release。业务动画在拖动时让位，但程序仍接收并保存最新有效状态。禁止松手时无条件恢复“按下鼠标前的状态”。拖动中完成的演示不等于真实 Codex 联动。

| 情况 | 建议表现与交接要求 |
| --- | --- |
| 按下后马上松手 | 立即进入 release，不强制把 pickup/hold 播完；落下首帧衔接要视觉检查 |
| 拖动中收到完成/失败 | 保持拖动姿态；松手后仅在该事件仍有效且仍对应当前展示任务时播放一次提示。否则按最新状态恢复，不重放旧提示 |
| 拖动中状态变为 working/waiting | 松手落稳后进入最新循环，从该动作定义的入口帧开始 |
| 拖动中来源断开或事件过期 | 松手后用中性姿态并显示 unknown/离线，不恢复之前的工作或庆祝动作 |
| release 尚未结束再次按下 | 允许立即重新 pickup；不堆积多次 release |
| 提示动画中出现更新任务状态 | 新有效状态可以中断提示；提示播完不产生业务 completed 事件 |
| completed/failed 播完且业务仍保留终态 | 回中性姿态，但由程序保留对应终态标识；视觉回中性不等于任务变成 idle |
| 多任务、重复、乱序或过期事件 | 联动层给出筛选后的展示状态与是否需提示；素材层不自行选择任务、重播同一完成事件或编造新鲜度 |
| 鼠标捕获丢失/取消拖动 | 程序需结束悬停并恢复有效状态，不能卡在 drag-hold；是否播放 release 由窗口可见性和位置恢复逻辑决定 |

不在本提案规定 JSON 字段、事件版本号或 TTL 数值。上述“有效”“当前展示任务”“提示已消费”的判定及拖动锚点映射由统筹协调程序、联动任务确定。光标与窗口的原始抓取偏移应稳定，不能因每帧透明包围盒变化而跳动。

## 6. 文件组织和加载需求提案

推荐先保留逐帧 PNG，便于美术检查和差异定位；运行时可按每动作横向条带导出。两者都使用固定画布，不自动裁切、不旋转打包。每动作条带有利于独立返修；全局大图集可减少文件数，但会让无关动作随重新排布变更。首阶段不冻结打包方式。

建议命名为 `aemeath_<clip-id>_<frame-index>.png`，帧索引三位、从 `000` 开始；例如 `aemeath_drag-pickup_000.png`。动作名小写连字符，不在文件名塞入任务 ID 或用户内容。单动作条带可命名 `aemeath_<clip-id>_strip.png`，按帧索引从左到右，宽=帧宽×帧数、高=帧高，不留未定义空格。以 1× 六帧为例，条带为 576×104；导出倍率改变时整包统一换算。

播放器未来至少需要知道：素材版本、像素倍率、统一帧尺寸、固定锚点、动作标识、帧位置/文件、逐帧毫秒时长、循环或单次、入口/出口姿态。这是一份能力清单，**不是可直接实现的 manifest schema**。字段名、路径根目录、图集间隔及校验规则由统筹接受后另行定义，不在本次新增 manifest 或生产素材目录。

建议资源损坏时使用已校验的中性静帧；若中性帧也不可用，程序显示明确素材错误及退出入口，不能以完全透明的窗口假装加载成功。素材的回退不应掩盖状态来源断线。

## 7. 后续视觉与行为验收

本节是未来验收计划，尚未执行；不将文档提交等同于测试通过。

1. 先做 idle-soft 试样：在 1×/2×/3× 下逐帧查看，再连续播放。对照游戏像素造型与第二版概念方向，核对头身比、粉发、蓝饰和羽饰，获得造型认可后再扩展动作。
2. 在白、深灰、彩色背景及透明棋盘上检查：无灰底/白边、无裁切、颜色不脏，全部帧尺寸一致。固定锚点叠加观察，除明确设计的抬升/下沉外，落地基线不漂移。
3. 检查循环尾帧→首帧和单次入口/出口：无突然缩放、重心跳变、羽饰瞬移；逐帧时长合计与动作表一致。动作被中断时也需检查，不只看完整播放。
4. 自动素材校验待实现：图片可解码、尺寸/倍率一致、alpha 规则满足、时长为正整数、帧序号完整、引用存在、条带帧数一致。此任务未添加镜像实现的测试。
5. 程序与联动实现后验证真实风险：按下即松手、拖动中完成、松手前完成已过期、拖动中断连、release 中再抓起、鼠标捕获丢失、重复完成不重播、任务切换不庆祝旧任务。先在明确标注 mock 的播放器测转换，再在真实 Windows 窗口测捕获、DPI 和位置恢复。
6. 只有通过实际视觉检查的素材才能称“可用”；只有真实运行后的程序才能称“桌宠可运行”；只有真实受支持来源驱动才能称“Codex 联动”。减少动作模式可只保留中性姿态及必要拖动反馈，其设置入口归程序决定。

## 8. 交接与待统筹决定

本提案可供程序评估动作容量、逐帧时间、固定锚点和中断需求，可供测试任务编写风险场景；其他任务目前不能把其中任一字段或数值当作已接受接口。

需要统筹一起决定：

- 是否接受独立桌宠方向；若选择内置皮肤，哪些待机/拖动需求明确降级。
- 是否以 96×104 逻辑网格、(48,94) 锚点做首个试样；实际窗口大小和 DPI 映射由程序验证后确定。
- 是否接受基础 47 帧容量和逐帧时长；idle-perform、机甲相关动作继续延期。
- 素材 manifest/条带导出格式、有效事件筛选和拖动后提示策略由谁落实到共享接口。

建议下一步：统筹接受方向与试样规格 → 进一步核定视频候选段 → 动画任务制作并视觉验收 idle-soft → 冻结素材接口 → 分批制作拖动和状态动作。本阶段没有制作、安装或运行桌宠，也没有验证真实事件来源。
