# PM 任务卡与派单规则

任务卡是各专题任务的执行边界；Issue 记录需求，PR 记录交付，PM 工作台记录状态。不能仅凭角色名称扩大职责。用户的新指令优先于任务卡；任务卡和旧简报冲突时，由 PM 解释并修订卡片。

## PM 职责

PM 维护需求、卡片、范围、依赖、里程碑和决策记录，验证交付证据，安排独立评审后协调合并。用户保留产品方向、最终外观及公开发布决定。日常调查和任务卡范围内的工作不重复请求许可。

## 统一完成定义

1. 交付对应任务卡的目标，差异仅在允许路径。
2. 有实际证据与适用验证；未验证的项目明确标记。
3. 提交/分支/PR 可追溯，跨模块冲突已解决或被 PM 明确接受。
4. PM 验收前仅能标“待验收”，不能自行宣告整个里程碑完成。
5. 拒收时由 PM 指出具体不满足项，以同一张卡的修订补充，不创建重复工作。

## 状态流转

待派发 → 已派发 → 执行中 → 待验收 → 已验收；遇阻转为阻塞，并写明缺少的输入、影响和恢复条件。消息发送成功只能证明已派发，不能证明已执行。

每张卡记录版本。范围变更必须由 PM 更新版本、文件所有权与验收条件，再通知对应任务。评审不等于修改被评审模块的授权。
