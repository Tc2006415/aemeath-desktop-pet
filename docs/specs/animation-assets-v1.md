# 最小动画素材契约 v1（候选）

状态：ART-002 v1.0 待 PM 验收及统一接受；2026-09-16。本文是一套单一推荐格式，尚非已冻结公共接口，也不授权实现。用户已确定独立 Windows 桌宠；不再保留内置皮肤或图集作为本版格式选项。

决策依据：PM 提交 `bf673927d3d88a6da071bfe49c3ec1aaa4fadb2b` 的 AGENTS、README、项目状态及 ADR 0001；专业输入为 DEV `02626be`、ART `d54730b`、INT `4782cd5`、QA `841021e` 的已提交提案。它们提供职责和风险依据，不把其中旧的未定方案或候选秒数当作现行接口。本文被 PM 接受后，在本文覆盖的素材格式、动作范围和加载规则上替代 [动画提案](../proposals/animation-spec.md) 的开放选项；历史视频证据及其限制继续保留。

## 1. 包布局和像素坐标

唯一布局为一个本地素材包目录，根下 `manifest.json`，帧文件置于其直接子目录 `frames/`。不支持 ZIP、网络 URL、条带、图集、裁剪坐标、APNG、脚本或热加载。manifest 为 UTF-8 JSON 对象，无注释、尾逗号或重复属性名；读取时允许 UTF-8 BOM。全包先校验、解码并缓存，再启用播放，播放中不重新打开帧路径。换包须重新走同一加载过程。

- 源帧固定 **96×104 逻辑像素、1×、8-bit RGBA 静态 PNG**。不接受调色板、灰度或16-bit PNG作为此候选格式，导出方先转换；图片分辨率元数据不影响逻辑尺寸。
- 每帧坐标原点左上，x向右、y向下；固定锚点为 **(48,94)**，落地基线为 y=94 的边界。锚点是画布坐标，不要求对应不透明像素；拖动悬空时也不变。
- 不根据 alpha 包围盒裁剪、自动居中、重算锚点或改变命中区域。不同帧可在同一画布内改变姿态，位移和接触点变化必须是明确的动作设计。
- alpha 仅取0或255；每帧至少有一个不透明像素。不烘焙灰底、棋盘格底或柔边阴影。建议角色可见区域 x=4…91、y=4…99，留白是视觉验收项，非解码器硬性裁剪规则。
- 宿主把逻辑坐标统一换算到自身窗口/屏幕坐标；显示使用最近邻采样。本文不另立 DIP、物理像素或混合 DPI 换算接口，具体换算由 DEV 候选经 PM 统一接受。

## 2. manifest 字段与精确名称

所有下列字段必填；不允许 null。各层未列出的字段拒绝，以免拼写错误被静默忽略。对象属性顺序无意义；`frames` 数组顺序就是播放顺序，不扫描目录、不按文件名重新排序。数值必须是 JSON number 的有限数学整数，字符串和布尔值不能代替数值。没有额外的 `frameCount`、fps、总时长或每帧锚点字段，避免形成两个时间/数量来源。

| 位置 / 字段 | 类型及候选约束 | 语义 |
| --- | --- | --- |
| 根 `schemaVersion` | integer，固定1 | 格式主版本；未知版本拒绝，不猜测兼容 |
| 根 `packageId` | string，`^[a-z][a-z0-9-]{0,47}$` | 素材包标识，不含任务或用户信息 |
| 根 `packageVersion` | string，三段非负整数 `0.0.0` 形式，除0外不带前导零，每段最多4位 | 素材修订标识；内容更改需递增版本，不改变schema语义 |
| 根 `packageKind` | string：`diagnostic` 或 `character` | 诊断用途或角色用途声明；不是视觉验收通过标志 |
| 根 `sourceScale` | integer，固定1 | 源帧倍率；不允许混装2×图片 |
| 根 `frameSize` | object：`width:96`、`height:104`，均integer | 全包统一画布 |
| 根 `anchor` | object：`x:48`、`y:94`，均integer | 全包统一逻辑锚点 |
| 根 `fallbackAction` | string，固定 `neutral` | 必须引用存在且通过校验的中性动作 |
| 根 `actions` | object，键是第3节动作ID，1–6个且必须含 `neutral` | 动作ID只出现于键，不再添加另一个id字段 |
| 动作 `playback` | string：`loop` 或 `once`，按第3节固定 | 循环或单次；不由帧数推断 |
| 动作 `origin` | string：`diagnostic`、`original` 或 `adaptation` | 制作来源性质；角色包按第3节取值，诊断包全部为diagnostic |
| 动作 `frames` | 非空array，每项是帧对象，最多64项 | 允许多个项引用同一图片；每次引用仍算一帧时序项 |
| 帧 `path` | string，按第5节限定为包内PNG路径 | 同一文件可跨动作复用，不能引用其他动作来代替帧 |
| 帧 `durationMs` | integer，1–10000 | 本帧完整显示时长，单位毫秒 |

单动作总时长为 `sum(frames[].durationMs)`，不超过60000 ms。资源限额是本候选的加载器常量，不由manifest自行放宽。修改允许字段、动作ID集合、固定尺寸或时间语义需 PM 评审新版契约；`packageVersion` 不能绕过 `schemaVersion`。

## 3. 第一角色包的动作范围

本版允许的动作ID仅下列六个，大小写精确匹配。第一角色包交付必须全部具备并通过校验，共建议25个时序项；不以原提案47帧为首包门槛。帧数和时长除 neutral 的单帧约束外均为制作建议，可以在限额内调整，播放代码不得写死它们。

| 动作ID | playback | 角色包origin | 建议时序及合计 | 正常结束/中断 |
| --- | --- | --- | --- | --- |
| `neutral` | `loop` | `original` | 必须恰好1帧，建议[1000]，1000 ms | 静态中性回退；不表示业务idle |
| `idle-soft` | `loop` | `original` | [400,150,150,400,150,150]，1400 ms，6帧 | 持续轻呼吸，允许立即被新播放请求替代 |
| `idle-smile` | `once` | `adaptation` | [120,120,500,120,120,220]，1200 ms，6帧 | 一次笑脸后回中性，由协调层决定下一动作 |
| `drag-pickup` | `once` | `original` | [80,80,100,100]，360 ms，4帧 | 正常结束且仍在拖动时可由协调层请求hold；提前松手可立即替代 |
| `drag-hold` | `loop` | `original` | [180,180,180,180]，720 ms，4帧 | 拖动期间悬停；松手/捕获丢失由协调层结束 |
| `drag-release` | `once` | `original` | [80,100,120,160]，460 ms，4帧 | 一次落稳后回中性；允许重新抓起而中断 |

`neutral` 不与旧提案的 `status-unknown` 并存为同义ID；后者不属于v1。`task-working`、`task-waiting`、`task-completed`、`task-failed`、`idle-perform` 均不在本版字段枚举或首包内，后续另行扩展。业务状态文字、模拟标识、未知/离线标识由宿主持续呈现，不能由中性素材替代或清除。没有任务动作时用 neutral 配合状态标识，不将 idle-smile 当作默认成功庆祝。

来源说明：idle-smile 只借鉴指定游戏视频中可见的像素闭眼笑与正向姿态，固定位置的开闭眼补帧及收势为桌宠改编；neutral、idle-soft 和拖动三段为沿用已选造型的原创动作。参考 [ART-001观察记录](../proposals/animation-spec.md#11-art-001-本轮实际视频复核) 和 [第二版概念图](../../assets/concepts/aemeath-game-style-v2.png)。4–10秒采样、约±1秒定位及缺失出场/闭环证据的限制仍有效，不承诺完整逐帧复刻；本轮不追加视频考据。

## 4. 播放语义与职责边界

播放器根据单调经过时间定位帧。第i帧占用区间 `[前i帧时长之和, 前i+1帧时长之和)`；恰好到边界选择下一帧。loop 按总时长取模；neutral 的单帧无需为每次循环产生结束通知。once 到总时长即结束，结束只发生一次，转 neutral，并让表现协调层据最新输入选择下一动作；协调层若同一调度时点给出新动作，无需强制显示一屏中性帧。

请求替换动作从新动作第0帧开始，旧动作立即取消，不再发出“自然播放结束”结果；实现须用等价的播放实例身份抑制旧回调覆盖新动作，不在本文冻结宿主函数签名。掉帧时跳到当前应显示的帧，不补播积压；一次动画即使跨过全部时长也只能结束一次。`drag-release` 的460 ms来自建议帧列表，**实际结束只能使用当前manifest的合计时长**，也不是业务状态有效期。

素材不包含nextAction、业务状态、事件时间、TTL或来源地址；因此不存在素材控制的动作跳转图。pickup→hold、松手→release和release后恢复最新有效状态均由唯一表现协调层决定。release期间业务状态继续更新，结束时再次检查有效性；此处不定义INT状态阈值或终态提示许可。动画播完不产生业务完成，不自动把unknown改为idle。

缺失/停用动作的请求应返回一次明确的“不可播放”结果并显示neutral，不能伪装成该动作自然结束，不能内部不断重试或排队。协调层仍负责解除拖动覆盖并重新选择当前表现；不能因缺少release而永远等待它的结束通知。

## 5. 路径、资源限额及错误处理

路径使用正斜线和小写ASCII，唯一语法为 `^frames/[a-z0-9][a-z0-9_-]{0,63}\.png$`。这是完整字符串匹配。禁止绝对路径、盘符、反斜线、`..`、URL、UNC、查询串、百分号编码和NTFS流语法；不做URL解码。文件名主体不得为Windows保留设备名 `con/prn/aux/nul/com1…com9/lpt1…lpt9`。所有引用均相对于manifest所在包根；精确名称匹配，不靠系统大小写折叠修正拼写。

宿主只加载明确指定的本地包根；在打开文件前确认规范化后的目标仍在包根内（目录分隔符边界比较，不能只做字符串前缀）。包根、frames目录和被引用文件不得是符号链接、junction或其他reparse point，不跟随链接到外部；用同一受验证路径打开并解码缓存，拒绝解析/打开时发现路径已变化的情况。不自动递归扫描包目录，未引用文件不加载、不计作动作。路径校验失败是整包错误，不能为了回退再尝试打开该路径。

| 限额 | 最大值（含边界） | 计算方式 |
| --- | --- | --- |
| manifest文件 | 64 KiB | 读入前/读入时限制，JSON解析深度最多8层 |
| 动作数 | 6 | actions键数；未知ID另按格式错误处理 |
| 单动作/全包时序项 | 64 / 256 | 包括重复图片引用的每个frames项 |
| 不同图片数 | 128 | 按精确path去重 |
| 单PNG/全部引用PNG压缩字节 | 256 KiB / 8 MiB | 全包按不同文件计数；不按引用次数重复累计 |
| 解码尺寸与原始像素缓冲 | 每图96×104；最多5,111,808 bytes | 128×96×104×4，约4.88 MiB；读取头部先拒绝尺寸/格式不符，再完整解码确认 |
| 单帧/单动作时长 | 10000 / 60000 ms | 均正整数；求和采用可检查溢出的整数算术 |

上述原始像素字节不是进程内存承诺；解码器临时缓冲、框架对象和GPU副本另由DEV评估，不将文件大小当成解码成本。一个引用在解码后由缓存复用，不为每个时序项复制整张图。

推荐错误策略如下，均保留宿主可访问的错误提示和退出入口，不把素材错误当成业务failed：

| 情况 | 加载/播放结果 |
| --- | --- |
| JSON语法、重复键、未知字段/版本/动作ID、类型、origin、playback、尺寸/锚点声明、帧时长或数量不合法 | 拒绝整包，报告格式错误；不以猜测的默认值播放 |
| 路径不合法/越界/reparse point，或任一资源限额超出 | 拒绝整包，在昂贵解码之前尽早退出 |
| neutral缺失、不为单帧loop、origin不符，或其中性PNG缺失/损坏/全透明/尺寸或alpha不符 | 拒绝整包，不从其他动画随取一帧冒充neutral |
| 非neutral动作缺失 | 其ID不可播放；请求时回neutral，报告动作缺失。可供诊断或不完整预览，不满足第一角色包交付门槛 |
| 非neutral动作引用的PNG缺失、解码失败、非规定PNG格式、尺寸/alpha不符或全透明 | 停用所有引用该坏帧的整条动作，不跳过坏帧、不缩短时间；其余已校验动作可用，包标记降级。若同时被neutral引用，则整包拒绝 |
| 新包拒绝且已有已加载有效包 | 保持旧包并报告新包错误；不得写成切换成功 |
| 首次加载整包拒绝、没有旧包 | 宿主显示独立于素材的可见错误及退出入口，不留下不可操作的透明窗口 |

字段元数据错误与帧内容错误的处置不同：前者整包拒绝，后者可停用非neutral动作。任何降级都记录具体动作ID与受限错误类别；不打印包外文件内容。只在后续显式重载时重试，避免逐帧报错和无限加载循环。

## 6. 可解析的最小诊断示例

下面是**文档示例**，不是随仓库交付的可加载素材包。只有JSON文本，未生成或校验PNG。为减少重复，示例用三张假定的诊断帧复用出六条动作；帧内可在将来绘制不同编号/标记用于检查时序与锚点，但不能称角色成品。本例release为280 ms，刻意不同于角色建议460 ms，以明确时间由manifest驱动。

假定文件清单（所有图片均应符合第1节，此次未提供）：

```text
diagnostic-v1/
  manifest.json
  frames/neutral.png
  frames/pose-a.png
  frames/pose-b.png
```

```json
{
  "schemaVersion": 1,
  "packageId": "diagnostic-v1",
  "packageVersion": "0.1.0",
  "packageKind": "diagnostic",
  "sourceScale": 1,
  "frameSize": { "width": 96, "height": 104 },
  "anchor": { "x": 48, "y": 94 },
  "fallbackAction": "neutral",
  "actions": {
    "neutral": {
      "playback": "loop",
      "origin": "diagnostic",
      "frames": [{ "path": "frames/neutral.png", "durationMs": 1000 }]
    },
    "idle-soft": {
      "playback": "loop",
      "origin": "diagnostic",
      "frames": [
        { "path": "frames/neutral.png", "durationMs": 400 },
        { "path": "frames/pose-a.png", "durationMs": 200 }
      ]
    },
    "idle-smile": {
      "playback": "once",
      "origin": "diagnostic",
      "frames": [
        { "path": "frames/pose-b.png", "durationMs": 300 },
        { "path": "frames/neutral.png", "durationMs": 200 }
      ]
    },
    "drag-pickup": {
      "playback": "once",
      "origin": "diagnostic",
      "frames": [
        { "path": "frames/neutral.png", "durationMs": 80 },
        { "path": "frames/pose-a.png", "durationMs": 120 }
      ]
    },
    "drag-hold": {
      "playback": "loop",
      "origin": "diagnostic",
      "frames": [
        { "path": "frames/pose-a.png", "durationMs": 180 },
        { "path": "frames/pose-b.png", "durationMs": 180 }
      ]
    },
    "drag-release": {
      "playback": "once",
      "origin": "diagnostic",
      "frames": [
        { "path": "frames/pose-b.png", "durationMs": 100 },
        { "path": "frames/neutral.png", "durationMs": 180 }
      ]
    }
  }
}
```

本例预期：neutral=1000、idle-soft=600、idle-smile=500、drag-pickup=200、drag-hold=360、drag-release=280 ms；共11个时序项、3条不同图片路径，fallbackAction引用neutral。全部路径在假定文件清单内；这仅证明内部引用一致，不证明磁盘资源存在或图片有效。

诊断包可只含有效neutral，供最早加载验证；要验证loop/once及中断至少使用本例中的相应片段。宿主加载diagnostic时须显示“诊断素材”标识。改为character必须同时更换真实角色图片、正确origin及版本，并经过第7节门槛；改一个packageKind值不能获得验收。角色包也不能仅靠自称character就隐藏降级错误。

## 7. 后续实际播放的必要视觉门槛（本轮未执行）

分开记录“格式可解析”“诊断播放通过”“角色视觉通过”。诊断帧只能证明播放器和交互行为，概念图不能替代角色帧。本轮只检查文档格式、示例解析与一致性，不新增测试工程，也不声称任一视觉门槛通过。

1. **诊断样机**：在真实Windows应用中检查一个loop、一个once及“pickup→hold→release”、快速松手/再次抓起的代表路径；用具有不同帧时长的诊断素材确认边界、只结束一次、取消无旧回调覆盖。素材损坏与越界按第5节做必要故障验证。终态TTL仍由INT/DEV共同基线另验，不能从release长度推断。
2. **第一角色包**：在一个明确记录的基准显示配置中实际播放六个动作；检查至少两个循环周期、一次完整笑脸、一次完整拖动与一次快速中断。看粉发/蓝饰/羽饰/紧凑比例、基线、首尾接续、透明边缘及裁切，在浅/深背景各看代表性待机和拖动姿态；用户仍保留最终外观决定。
3. **缩放代表组合**：源帧1×静态检查，加应用常用显示倍率下的运行检查；只选neutral或idle-soft与拖动序列，在一组不同DPI的跨屏/缩放切换中验证清晰度、锚点和裁切。不存在实测设备时该项记未验证，不要求“所有动作×所有DPI”笛卡尔积。若发现裁切、锚点漂移或某动作特有问题，再扩大到受影响动作和配置。

记录素材packageId/version、应用提交、显示配置、观察动作、实际结果及截图/短录屏；记录未验证设备和缺失动作。坏neutral导致启动错误不可见、不能退出、拖动永久悬停或旧动作回调覆盖新动作属于阻断问题。单次通过不代表全视频复刻、真实Codex联动或发布通过。
