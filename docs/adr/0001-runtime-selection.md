# ADR 0001：桌宠运行方式

状态：已接受运行方向（2026-09-16）；技术栈和共享接口另行冻结。

## 背景

用户需要游戏内像素爱弥斯、丰富待机、拖动反馈及 Codex 任务状态联动。已查明当前 Codex 内置自定义图集有固定动画槽，待机使用 6 帧；没有确认任意多套待机和拖拽动画的可配置入口。

## 候选

1. 内置兼容皮肤：保留原有整合，但需要精简动作，不能承诺完整满足行为需求。
2. 独立 Windows 桌宠：自行控制动画和拖动；任务联动作为独立适配层，必须验证真实事件来源。

用户已明确选择“做独立 Windows 桌宠”。采用第二项，内置兼容皮肤不属于首版交付。独立程序不修改、注入或重打包 Codex 安装文件。

## 决策及实施顺序

- 首版目标为 Windows 11 x64；C# / WPF / .NET 为优先验证候选，具体 SDK 和工具链由程序任务核实后交 PM 冻结，不把候选当成已实测技术栈。
- 先统一最小素材、坐标、状态接口，再制作诊断样机；角色素材和模拟状态在接口确定后并行推进。
- 首版只展示一个选定任务，暂不做多任务聚合、外观编辑器和复杂表演动画。
- 独立运行与真实 Codex 联动分开验收。未接入来源时显示未知/离线，模拟模式明确标注；真实来源尚未证实，不承诺外部程序能够订阅 Codex Desktop。
- 本次接受运行方向，不代表已有可运行桌宠，也不自动开始工程实现。下一轮任务收敛接口和必要测试，随后由 PM 派发具体实现任务。
- 每步按风险测试：必需检查未执行记待验；低影响文案不写镜像测试；不以覆盖率或穷举组合代替关键行为验证。

## 决策依据及后续门槛

- 程序任务说明可用工具链、透明窗口和多 DPI 的验证路径。
- 联动任务说明是否存在受支持且可访问的状态来源；未找到时给出诚实的独立运行降级方案。
- 素材任务提供游戏风格的帧尺寸、动作容量和播放需求。
- 用户已明确选择独立 Windows 桌宠；程序、动画、联动与 QA 的本轮文档交付已由 PM 验收。后续仍需冻结技术栈与共享接口，并取得真实运行证据。
