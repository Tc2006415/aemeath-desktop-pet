## 目标

为 PM 提供可执行验收标准，并独立检查四份提案的边界与一致性。

## 输入与依赖

阅读 AGENTS.md、docs/task-cards/README.md、docs/project-status.md 和 ADR 0001。交叉审阅时读取以下已提交版本，不需要合并其他分支：程序 42090e8、动画 c78a545、联动 9a01b91、测试 e96dd65。可使用 git show <commit>:<path>；不能将他人的未接受提案当作正式接口。

## 允许范围与文件所有权

只读审阅其他任务分支的文档；编写验收矩阵和 M1 文档评审报告；指出冲突、缺失证据和未决接口。

唯一允许修改的交付路径：docs/proposals/acceptance-matrix.md；docs/reviews/m1-proposal-review.md。

## 禁止范围

不得代替程序/动画/联动任务改代码或规格；不得自行豁免失败或改变产品范围；不得把文档检查写成运行时测试通过。 不得自行合并、公开发布、创建额外任务或修改本任务卡。

## 本轮具体任务

在 docs/reviews/m1-proposal-review.md 对四个已提交提案作独立一致性检查。逐项列出文件、小节、影响、责任人、建议决策；区分真实冲突、正常未决项及非阻塞建议。审查点包括拖动中任务变化、终态去重、新鲜度、像素锚点、DPI 和验证能力。不要修改别人的提案。

## 验收条件

报告可追溯到具体提案及提交；明确哪些是 M2 阻塞；无凭空实测结论；所有测试用例有输入/预期/证据。

文件差异必须在允许路径内；git diff --check 无错误；交付包含实际使用的来源或命令和未验证项。提交到上述分支，更新已有 Draft PR；无需重复创建 PR，也不关闭原 Issue。若查不到 PR，报告分支与提交即可。

## 交接格式

按“任务卡编号 / 状态 / 基准与交付提交 / 修改文件 / 验证证据 / 未验证及风险 / 待 PM 决定事项 / PR 链接”提交。状态只能是执行中、阻塞、待验收；完成由 PM 验收后标记。

## 越界与阻塞处理

需要改动其他文件或接口时，先提交变更请求，写明原因、影响、最小范围和备选方案；继续完成不依赖该决定的授权工作。不要让用户重复批准已有任务范围。交付后等待下一张任务卡，不自动进入下一里程碑。
