## 结论与实施门槛

建议在统筹接受独立桌宠方向后，优先验证 **C# / WPF / .NET**，备选 **TypeScript / Electron**。这是根据 Windows 单平台、透明小窗口和交互需求作出的工程判断，尚无性能实测。当前只完成只读调查和本提案，没有安装 SDK、创建运行时工程、确定依赖版本或修改 Codex。

WPF 的窗口和输入路径较贴近 Windows，适合本项目的有限 UI；Electron 的 Canvas 动画表达方便，但带入浏览器运行时，并有透明窗口、拖动区域及点击穿透限制。两者都需要原型实测，不能仅凭 API 文档认定满足需求。ADR 0001 仍由统筹接受；内置兼容皮肤的槽位限制沿用仓库调查，未在本任务重新核验，也不把独立桌宠推荐当作用户已选定方向。

开始实现前需要：统筹确认运行方式和候选技术栈；动画、联动、测试提案汇合；确定共享素材与状态语义。随后只实现一个可丢弃的 Windows 验证样机，再决定是否进入 M2。不得因提案合并自动安装工具链、接入私有状态源或公开发布。

## 内部职责与跨任务需求（均为建议）

程序内部划分四个职责，不在这里定义语言类型、JSON 字段或 IPC 通道：

1. **桌面宿主**：窗口、命中、拖动、工作区、DPI、托盘/设置、持久化和退出。
2. **状态协调**：接收被认可的业务状态，保存最新有效快照；将任务状态与临时交互状态合成为展示意图。
3. **动画播放器**：只认素材片段及播放请求；按单调时钟推进，报告一次性动作结束。不根据帧播完推断任务完成，不自行访问 Codex。
4. **输入适配边界**：真实来源和显式模拟器分别接入。模拟入口常驻显示“模拟”；无已验证来源时显示“未知/离线”，仍允许角色独立待机。

### 需要动画任务提供的语义

素材版本、透明 PNG 或图集布局、源帧尺寸与裁切范围、统一脚底/锚点、逐帧时长、循环或单次动作、动作中断/收尾规则、缺失动作回退、原始像素网格以及推荐展示倍率。拖动中姿态变化也须保持锚点，避免角色跳离鼠标。

程序不指定最终帧宽高、文件名、槽位、帧数或格式版本。内置皮肤的 192×208 和固定 6 帧不是独立桌宠规格。需要动画任务区分游戏观察动作与为桌宠原创的拎起、拖动、放下动作。素材路径限已批准的本地目录；加载器须拒绝越界裁切、非法时长、缺失/损坏图片并限制解码资源量，具体上限随素材规格共同确定。

### 需要联动任务提供的语义

能够区分 idle、working、waiting、completed、failed、unknown 的状态；任务身份、事件身份或可去重序号、产生时间/顺序依据、接收新鲜度、来源真实性和连接状态。需要明确快照与增量区别、断线/过期判定、终态有效期、恢复连接及多任务汇总策略。

这些是消费者需求清单，不是正式协议。不得把上述词汇直接实现为程序自创的外部 schema。多任务优先级、终态停留时长、允许的时间偏差、传输方式均由统筹结合联动提案决定。业务新鲜度与动画播放时钟分离，避免修改系统时间造成动画或过期逻辑异常。

### 拖动与任务变化的建议行为

拖动为临时视觉覆盖层，不替换业务状态。按下时进入拎起/拖动；期间继续接受合法业务更新；松手或失去鼠标捕获后结束覆盖，从**最新有效业务快照**重新选择动作，不能恢复按下时保存的旧动画。

例如 dragging 期间收到 completed，界面保持拖动姿态；松手时若完成状态仍新鲜且符合最终展示策略，显示完成动作一次；若已过期则显示未知/离线。重复终态不得重复触发庆祝，过时事件不得覆盖较新状态。去重与排序的责任归属必须在共享协议中唯一明确。拖动期间若依次发生 completed→working，应按最新 working 恢复，不补播旧庆祝。没有完成动画时允许中性姿态加文字状态，不能伪造角色动作已完成。

以下全部是 **未执行的后续验收计划**。实现须等 ADR 与接口接受；样机素材可用明确标记的诊断色块/测试帧，只检验渲染与交互，不作为角色成品交付。建议每次记录 OS、框架版本、显示器分辨率/缩放、步骤、实测现象和通过/失败，不收集其他应用内容。

| 编号 / 能力 | 最小方案与操作 | 通过标准 / 证据方式 |
| --- | --- | --- |
| R1 透明窗口 | 启动紧凑无边框窗口；在深浅桌面背景上检查四周，切换前台应用 | 无实色背景块、不抢键盘焦点；实际窗口截图/人工记录。置顶可关闭；不承诺覆盖安全桌面或独占全屏 |
| R2 动画 | 两个循环片段及一个单次测试片段；前后台切换、暂停后恢复、模拟低帧率 | 时间推进稳定、单次只结束一次、不会积压补播；虚拟时钟单测＋实际帧录制；正式角色仍需独立视觉验收 |
| R3 拖动 | 拎起、快速移动、窗口外释放、失去捕获、跨屏；同时送入模拟完成/失败/新工作事件 | 光标与锚点无明显跳变；所有结束路径均退出拖动并取最新有效状态，无永久卡住姿态；状态转换单测＋真实鼠标操作 |
| R4 缩放 | 初步比较 1×/2×/3×逻辑倍率，在 100%/125%/150%/200% 系统缩放下查看 | 最近邻采样无明显模糊、无遮挡、锚点稳定、命中随尺寸变化；若非整数物理像素造成不均匀，记录并由统筹选择逻辑尺寸或物理像素对齐策略 |
| R5 退出与恢复入口 | 托盘菜单含“设置/移回当前屏幕/退出”；设置窗口有键盘可达退出；测试托盘折叠及键盘导航 | 不依赖角色小面积右键才能退出；退出后进程/计时器关闭、无孤儿窗口；真实 Windows 操作 |
| R6 位置保存 | 松手及倍率变更后延迟合并保存；重启、写入失败、损坏配置 | 保存显示器参考与工作区相对位置、倍率及版本；临时文件原子替换候选方案；坏配置回退可见位置并可提示，不崩溃；文件读写/边界测试 |
| R7 多屏 | 副屏位于主屏左/上形成负坐标；跨不同 DPI；拖动中拔除屏幕、改主屏、变任务栏工作区 | 不把负数坐标当非法；窗口完整夹入仍存在的工作区；保存的屏幕不存在则移回当前可用屏幕；几何单测＋真实双屏操作 |
| R8 DPI | 在不同缩放屏间往返，停留后改变系统缩放 | 明确唯一坐标单位与转换边界；不重复乘缩放；重算尺寸后保留鼠标抓取偏移/脚底锚点，截图比对并记录误差；不能用浏览器设备模拟代替 |
| R9 状态异常 | 重复、乱序、断连、过期、重连及多任务事件，全部标注模拟 | 按最终共享协议验证；断连/过期不猜完成，模拟与真实来源可区分；假时钟/事件序列单测，真实联动另行验收 |
| R10 素材异常 | 坏 PNG、缺动作、越界帧、零/负时长、超大尺寸 | 可诊断地拒绝或回退，退出入口仍在；加载器边界测试，不以崩溃作为正常失败方式 |
| R11 打包 | ADR 后构建私有测试包，在未安装开发 SDK 的干净 Windows 用户环境启动、退出、重启 | 无需开发目录，资源路径正确，设置位于用户可写目录；记录包哈希/架构/日志。不设置开机启动、不自动更新、不公开上传 |

位置建议采用工作区内归一化的锚点位置，同时保留显示器参考作为提示；不能仅依赖可能变化的显示器编号。恢复时先匹配现有屏幕，再重新计算与夹取；倍率导致窗口大于工作区时限制显示尺寸或回退合适倍率。跨 DPI 时禁止把全局物理像素与局部 DIP 直接相减。最终存储 schema 和坐标约定在实现前由统筹确认。

R1/R3/R7/R8/R11 是技术选择的关键门槛。WPF 若无法在真实窗口验证透明渲染、拖动结束与 DPI 稳定性，提交失败证据后才申请改测 Electron；不同时搭建两个正式项目。性能基线在同一设备测冷启动、稳定待机和连续拖动的进程内存/CPU与包体积，阈值由统筹接受后再设为发布门槛。

| C2 松手时点与放下片段 | DEV 首稿写松手重新选择动作，未明确是否先放下；ART「4」「5」建议先播 460 ms drag-release 后进入最新业务表现；INT「多任务和拖动期间的展示」要求提示仍在候选 5 秒窗口内且未被新轮次取代 | 建议松手开始 release，但在 release 结束、捕获取消恢复及每次有效状态变化时重新计算，不能在松手时锁定待播完成。例：松手时终态年龄 4.8 秒，release 后超过 5 秒，则不庆祝；release 中重抓应立即 pickup。5 秒及 460 ms 都仍是候选值。影响 QA A02–A04/A15 |

| C4 状态筛选及提示消费的所有权 | ART「5」说联动层提供筛选后的展示状态与是否需提示；INT「与桌宠程序无关的协议草案」区分适配层、状态层和渲染层，且「顺序、去重与过期」第 4 条记录已展示标记；DEV「状态协调」也保存快照并合成展示意图，模块归属尚未统一 | 建议来源适配器只归一化，唯一状态归约器负责顺序、去重、新鲜度和任务选择，程序表现协调负责拖动与提示实际启动。提示在真正开始播放时消费；被更新中断后不重播；拖动遮挡期间不提前消费。具体归约器归属、调用边界及消费反馈由 PM 定义，避免两边各有 TTL/去重表。对应 QA A05/A06/A15 |
